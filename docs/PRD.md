# BBPlayer 桌面端 PRD

## 项目信息

| 项 | 内容 |
|---|---|
| 产品名称 | BBPlayer Desktop |
| 项目名称 | `bbplayer_desktop` |
| 定位 | B 站音频播放器的桌面端版本，功能完整对齐移动端原版 |
| 目标平台 | Windows / macOS / Linux |
| 语言 | 中文（用户语言） |
| 原始需求 | 为开源（MIT）BBPlayer（原 React Native + Expo 移动应用）开发桌面端版本，完整对齐核心播放、歌词、主题三大能力，并补齐桌面端特有交互 |

---

## 一、产品目标与定位

**一句话定位**：把 BBPlayer 从「手机上的 B 站音乐播放器」升级为「桌面上的 B 站音乐中心」，让用户在工作、学习、娱乐时用更自然的桌面交互听 B 站音频。

**三条核心价值**：

1. **全量功能对齐**：登录、歌单、播放器、歌词、主题等移动端能力在桌面端完整复刻，老用户零学习成本迁移。
2. **桌面原生体验**：托盘常驻、全局媒体键、桌面歌词悬浮窗、多窗口，让音频播放「不打扰」地融入桌面工作流。
3. **多源歌单聚合**：本地 + B 站收藏/订阅合集 + 网易云/QQ 音乐歌单导入，成为个人跨平台音频的统一入口。

---

## 二、目标用户与核心用户故事

**目标用户**：B 站重度用户（追 V 家/音乐区/鬼畜/直播录播等音频向内容），需要边干活边听、且希望集中管理多平台歌单的桌面用户。

1. 作为**上班/学习中的 B 站用户**，我想要把播放器最小化到系统托盘并用全局媒体键切歌，以便我在专注工作时不切换窗口也能控制播放。
2. 作为**桌面歌词需求用户**，我想要一个置顶、可拖拽、可调透明度/字体的歌词悬浮窗，以便我随时对着歌词听歌/学唱。
3. 作为**多平台听歌用户**，我想要把网易云/QQ 音乐歌单自动匹配成 B 站视频播放列表，以便我在一个应用里统一管理所有收藏。
4. 作为**老 BBPlayer 移动端用户**，我想要沿用原版的登录、主题装扮与断点续播体验，以便我无缝迁移到桌面端而不丢失习惯。
5. 作为**本地内容整理者**，我想要本地播放列表与播放历史持久化保存，以便我重启应用后继续上次的进度与歌单。

## 三、需求池

### P0（MVP 必须）

1. **B 站登录**：支持扫码登录、手机号短信验证码登录、手动设置 Cookie 三种方式。
2. **本地播放列表**：创建、编辑、删除本地歌单，并持久化保存。
3. **账号数据访问**：登录后访问 B 站收藏夹与订阅合集并转为可播放列表。
4. **基础播放器**：播放/暂停、上一首/下一首、循环（单曲/列表）、随机播放、播放队列、进度条拖拽。
5. **断点续播**：记录并恢复每个播放项的播放进度。
6. **启动自动播放**：应用启动后恢复上次播放上下文并可自动继续。
7. **搜索**：智能搜索（关键词 + BV/AV 号 + b23.tv 短链解析），并支持收藏夹与本地列表内搜索。
8. **LRC 歌词**：自动匹配歌词（网易云/QQ 音乐/酷狗音乐）、手动搜索、粘贴 LRC、偏移量调整。
9. **本地数据持久化**：歌单、播放历史、设置等本地存储。
10. **多窗口管理**：主窗口 + 歌词窗口独立存在与联动。

### P1（重要）

1. **桌面歌词悬浮窗**：无边框、置顶、可拖拽、可调透明度与字体大小。
2. **系统托盘常驻**：关闭主窗口时最小化到托盘，托盘菜单提供播放控制与退出。
3. **全局媒体快捷键**：注册系统级快捷键与 Media Session（系统媒体键），后台控制播放。
4. **主题装扮**：应用任意 B 站主题装扮（导航栏、开屏动画、进度条拖拽图标、点赞动画、页面头部背景、头像框）。
5. **导入外部歌单**：网易云音乐、QQ 音乐歌单导入并自动匹配到 B 站视频，保存为播放列表。
6. **响度均衡**：播放时对音频做响度归一化，避免音量忽大忽小。
7. **SPL 逐字歌词**：逐字进度高亮，支持罗马音注音与翻译歌词。

### P2（增强）

1. **状态栏歌词替代方案**：在托盘悬浮提示 / 标题栏滚动 / 桌面歌词窗之间切换歌词展示方式。
2. **播放历史**：独立的历史记录页与最近播放快捷入口。
3. **快捷键自定义**：允许用户自定义全局/应用内快捷键。
4. **多语言界面**：中英文界面切换。
5. **开机自启动**：可配置是否随系统启动并静默进入托盘。
6. **主题/设置导入导出**：备份与迁移用户配置。

## 五、待确认问题

1. **技术栈选型**：默认建议 Electron 或 Tauri？是否沿用 React + TypeScript 技术栈以便复用原版逻辑？（影响包体积、内存占用、跨平台能力与开发效率）
2. **登录实现方式**：B 站扫码/短信/ Cookie 登录是否需要复刻原版的 API 与风控策略？Cookie 的本地加密存储与过期刷新机制如何定？
3. **桌面歌词悬浮窗技术**：采用独立原生窗口（Electron BrowserWindow / Tauri WebviewWindow）还是单窗口内模拟悬浮？需要跨屏/多显示器支持吗？
4. **全局媒体键范围**：全局快捷键与系统 Media Session 的冲突处理优先级？macOS 下 Media Keys 监听需要特殊权限，是否接受？
5. **响度均衡算法**：是否复用原版的响度均衡实现，还是引入 Web Audio / FFmpeg 方案？对音质与性能的要求？
6. **外部歌单导入合规**：网易云/QQ 音乐歌单抓取与 B 站自动匹配涉及第三方平台，是否需要内置「仅匹配已有视频、跳过失效项」的容错与免责策略？
7. **多账号与登录态**：是否需要支持多账号切换、登录态持久化与登出？
8. **发布与签名**：Windows（安装包/免安装）、macOS（签名/公证）、Linux（AppImage/deb）的目标格式与自动更新机制？
